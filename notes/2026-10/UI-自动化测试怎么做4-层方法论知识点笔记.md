# UI 自动化测试怎么做：4 层方法论（知识点笔记）

> 来源：微信视频号《软件测试面试 / 自动化测试 / 测试开发》（UI 自动化实战心法）
> 提取方式：抽帧 → 画面 OCR → 整理
> 日期：2026-10-23

## 一句话总结
做 UI 自动化不要"拿锤子找钉子"。四层心法：**LAYER 01 先定"测什么"→ LAYER 02 图像识别拆解着用 → LAYER 03 隔离变化让脚本活得久 → LAYER 04 跳出测试从源头降成本**。普通测试和资深测试的差距，就在这四步。

## 核心要点
**LAYER 01 · 先搞明白"测什么"再想"怎么测"**
- 核心路径才自动化：立即购买按钮能不能点 / 优惠券弹窗弹不弹 / 价格文案对不对。
- 不值得自动：banner 换背景色、装饰元素挪两像素 → 让运营肉眼看。
- 上来就全量覆盖 = ROI 低到离谱，项目直接黄。

**LAYER 02 · 图像识别不是万能药，拆解着用**
- 坐标点击兜底：底部"立即参与"按钮永远最下方居中 → 用相对坐标点，管图片换成啥。
- OCR 校验关键文案：价格 / 活动时间 / 核心规则用 OCR 识别**内容**（不是匹配图片长相）。
- 局部特征匹配：只对按钮、弹窗等关键组件做特征点匹配，不整页截图比。
- 选对工具：`Airtest` / `Sikulix` 比手写 OpenCV 稳得多。

**LAYER 03 · 把变化"隔离出去"，脚本才能活得久**
- 配置和脚本分离：坐标 / 校验文案 / 图片模板全抽配置文件 → 运营换图你改配置，用例代码一行不动。
- 页面区域化拆解：长图切头部 / 活动区 / 底部按钮区 → 改中间 banner 不影响底部按钮。
- 多重定位兜底：一个按钮备 OCR → 图像匹配 → 固定坐标 **三级容错**。

**LAYER 04 · 跳出测试视角，从源头降低测试成本**
- 跟运营 / 设计约定活动页规范，从源头框住"变化范围"：关键按钮必须留底部 10% 安全区、价格数字统一字体字号、弹窗关闭按钮永远右上角固定。
- 结果：自动化脚本维护成本直接砍半——不是甩锅，是专业。

## 展开说明
- **普通测试 vs 资深测试**：拿到需求就写脚本 / DOM 能定位就写 / 定位不了就说"测不了" / 只在测试环节使劲 → 反之为先看场景算 ROI、选最合适方案、往前推规范、从根解决问题。
- 与 `004`（软件测试提效）、`006`（软件测试面试）、`013`（端到端测试）同属测试工程主题。
