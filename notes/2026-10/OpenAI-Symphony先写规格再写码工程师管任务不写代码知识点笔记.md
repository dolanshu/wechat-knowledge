# OpenAI Symphony：先写规格再写码，工程师管任务不写代码（知识点笔记）

> 来源：微信视频号《上线 72 小时，3000 Star，OpenAI 没开发布会，就扔了一个 GitHub 仓库》（核心为 openai/symphony）
> 提取方式：抽帧 → 画面 OCR → 整理
> 日期：2026-10-23

## 一句话总结
OpenAI 开源 **Symphony**（spec-driven 工作流），主张**重新设计软件工程流程**而非简单"AI 辅助写代码"：工程师从"管代码"转为"管任务/质量/方向"，AI 管代码。三步上手：放 `WORKFLOW.md` → 在 Linear 建任务 → 等着审代码。

## 核心要点
1. **范式转变**：以前工程师**管代码** → 现在工程师**管任务**，AI **管代码**。这一转变比任何具体工具都重要。
2. **普通开发者三步上手**：
   - 01 在仓库放 `WORKFLOW.md`：写清项目是什么、技术栈、任务完成标准。
   - 02 在 Linear 建任务：写清需求，Symphony 自动轮询任务列表。
   - 03 等着审代码：成果/测试/变更全整理好，看一眼合并。
3. **参考实现（Elixir）**：`git clone github.com/openai/symphony` → `mix deps.get` → `cp .env.example .env` → `mix symphony.setup` → `mix symphony.start`。
4. **核心原则**：不是 AI 替你想清楚怎么做，而是**你先想清楚、写下来，让 AI 照着做**（提前准备说明文档/项目结构/编码规范/常用操作）。

## 展开说明
- **历史类比**：1880s 电力普及，工厂主只把蒸汽机换成电动机、流程没变 → 效率没提升；正确做法是重新设计生产流程。AI 编程同理——Symphony 是"第一个真正重新设计流程"的工具。
- **与 spec-driven 关联**：即 `030`（GitHub 亲自下场：AI 编程先写规格再写码）同主题，Symphony 是该思路的开源落地。
- 视频标题"72 小时 3000 Star"为早期数据；重点是工作流范式。
